# Code of conduct

This is a small project with one maintainer. These are the terms for taking part in its issues, pull requests
and discussions.

## What is expected

- **Report what happened, not what you think of it.** An issue that pastes the gate's answer whole, with the
  versions it ran on, is a contribution. One that says the plugin is broken is not yet.
- **Say where a claim comes from.** This project's rule is that a model's memory is never the source for what a
  mod can do; hold a discussion to the same rule. Name the documentation page, the section of the design
  record, or the command you ran. "I ran it and it printed this" and "I read it here" are both fine; say which.
- **Say who made a decision.** Much of this repository was written by Claude sessions working for the owner.
  Text written by a model is welcome in an issue or a pull request; say that it is, and check it before you
  post it.
- **Disagree with the rule, not the person.** A gate that refused your build is a design decision with a
  recorded reason (`docs/mod-builder/SPEC.md`, section 7). Argue with the reason.
- **Keep security problems private** until they are fixed: see [`SECURITY.md`](SECURITY.md).

## What is not accepted

Insults, harassment, threats, sexual attention, publishing someone's private information, or a sustained
refusal to stay on the subject of an issue. Neither is an issue or a pull request submitted in bulk without
having been read by the person submitting it.

## What happens

The maintainer may edit, hide or remove a comment, close or lock an issue or a pull request, or block an
account from the repository, and will say why when doing so.

## Reporting

Report conduct to the maintainer through GitHub: <https://github.com/bankielewicz>. For a comment on this
repository, GitHub's own "Report content" on that comment also reaches GitHub's staff.
